**Meeting Summary**

Octavia and the user reviewed the lore directory redesign roadmap, focusing on step 2: designing the learn dialog (the skill that surfaces and records institutional knowledge). The user initially wanted to know whether the internal structure of `.lore/learned/` needed to be designed first, but clarified that this was over-specifying. The core issue being solved is the tendency of automated capture skills to produce verbose, plausible output where a single concept gets restated multiple ways without adding clarity.

The user reframed `/learn` from an automated extraction tool that scans build artifacts to a simple user-invoked dialog. The skill's job is to help the user record lessons when they recognize something worth saving — from debug sessions gone wrong, from reviewing Thorne findings, or from noticing patterns across time. The skill asks questions rather than asserts; the user names the lesson. If no coherent lesson emerges, the session ends without writing — "nothing" is a valid outcome.

The assistant initially started mapping out implementation details (dedup mechanics, file shape, lifecycle) and the user caught the mistake: applying template-thinking to an anti-template skill. The session converged on a kernel shape: user invokes, two-path opening (specific material or felt pattern), AI asks questions, user articulates, terse writing with content-driven length, active dedup before write, and clean exit if nothing emerges.

**Decisions Made**

- `/learn` is user-invoked only. No auto-fire from other skills like `/specify` or `/prep-plan`.
- Dialog opens with two-path question: "Do you have specific material you want to pull up, or are you describing a pattern you've noticed?"
- AI adopts question-first posture. It surfaces candidates and reflects back what it heard; the user names the lesson. The skill never asserts a lesson exists.
- Output is terse and content-driven. No length target or budget; some lessons are one sentence, some include code samples. Length follows what the lesson actually needs.
- Before writing, the skill searches `learned/` for related entries and surfaces them to the user, who decides whether to update an existing entry or create a new one. This directly addresses the retro pathology of repeating the same concept under different framings.
- A session can end without producing a file. If the user can't articulate a clear lesson, the answer is no output.
